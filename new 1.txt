Принимаем, что на текущий момент под проверками DQ понимается формирование спец витрин, содержащих информацию о результатах выполнения скриптов, проверяющих данные по каким-то алгоритмам. Конечная цель - построить аналитический дашборд, содержащий результаты таких проверок для дальнейшего исправления данных.

Все проверки делятся на две большие группы:

технические
бизнесовые
Технические проверки - это базовая простая логика, что можно делать по шаблону для множества объектов (например, проверка на обязательность заполнения полей, проверка на отсутствие дубликатов по ключу), ведутся обособленно от бизнесовых, объединены и выделены в отдельный блок реализации.

Так называемые "бизнесовые" проверки, с неординарной логикой, ведутся обособленно. Логика каждой такой проверки указывается в отдельном скрипте, чтобы соблюдалось правило - один скрипт - одна проверка. Если витрина содержит несколько бизнесовых проверок, то каждая такая проверка будет реализована отдельным скриптом в отдельном файле.

Скрипты с проверками добавляются в текущие сущности загрузки, подобно формированию обычных витрин.

Требуется создать централизованный "Справочник проверок", единый для всех направлений, содержащий основную информацию о проверке. Состав атрибутов справочника указан в файле: DQ.xlsx на листе "Справочник". Набор атрибутов обусловлен необходимостью построения аналитической отчетности по результатам прохождения проверок. Справочник будет использоваться при наполнении спец витрин с результатами проверки.

Два вида витрин: Краткая и детальные.

Краткая. Для всех направлений и всех проверок. Содержит агрегированную информацию о результатах выполнения каждой проверки каждого направления. Новые данные дописываются. Срок хранения записей 180 дней, чтобы иметь возможность строить аналитику в динамике, а более старые удаляются ежедневно.

Структура краткой витрины описана в файле DQ.xlsx на листе "Краткая витрина".

Над данными краткой витрины строится главная (обзорная) страница аналитического дашборда DQ.

Наименование краткой витрины: dq_overview

Детальные витрины. Содержат подробную информацию об ошибке, включая данные, которых будет достаточно для того, чтобы понять конкретную строку витрины, которая не прошла проверку (ключ строки). Для каждого вида проверки (error_code) своя таблица с деталями. Таблиц несколько, потому что их структура разная, в зависимости от вида проверки. Срок хранения записей в детальных витринах 30 дней, а более старые удаляются ежедневно.

Структура детальных витрин описана в файле DQ.xlsx на листе "Подробная витрина".

Наименование таблиц дается по id проверки. ID проверки содержит префикс dq_, функциональное направление и порядковый номер проверки, например, dq_sd0001

Результаты проверок, выполняемых над массивами данных, логируются только в краткой витрине с соответствующим текстом ошибки. Причина - невозможность собрать детальную информацию по ключам, так как сравниваются агрегированные множества.

Краткий и подробные логи находятся в схеме dm, подобно другим витринам, справочник проверок в dict_dds.

Какие-либо методики расчета метрик достоверности, расчет показателей достоверности и степени доверия пока не прорабатываются.

В базе знаний есть раздел с описанием "бизнесовых" проверок, сгруппированных по функциональным областям, например, Описание проверок. Сбыт. | База знаний
