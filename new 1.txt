docker exec -it table-dependency-viewer-api-1 sh -c "python -c \"from api.main import compute_order_breaches; rows=compute_order_breaches(); hits=[r for r in rows if
  r['target_fqn']=='dm_calc.statement_purchase_3_person']; print('BREACHES:', len(hits)); print(hits[:3])\""

  Если там будет запись, значит все окончательно:

  - расчет правильный
  - наружу мешает только старый cache /api/orderbreaches

  Тогда просто сбрось cache через уже существующий admin endpoint:

  curl --noproxy '*' -s -X POST http://127.0.0.1:15312/api/admin/refresh-cache \
    -H "Authorization: Bearer $TOKEN"

  И потом снова:

  curl --noproxy '*' -s http://127.0.0.1:15312/api/orderbreaches \
    -H "Authorization: Bearer $TOKEN"

  Если хочешь, можно еще жестче проверить именно cache-функцию:

  docker exec -it table-dependency-viewer-api-1 sh -c "python -c \"from api.main import get_cached_order_breaches; rows=get_cached_order_breaches(); hits=[r for r in
  rows if r['target_fqn']=='dm_calc.statement_purchase_3_person']; print('CACHED:', len(hits)); print(hits[:3])\""

  То есть сейчас гипотеза такая:

  - get_dependency_violations() уже верный
  - compute_order_breaches() должен быть верный
  - HomePage показывает старый _order_breaches_cache

  С высокой вероятностью refresh-cache это добьет.
