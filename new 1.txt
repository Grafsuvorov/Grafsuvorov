DROP TABLE IF EXISTS for_1079_base_small;

CREATE TEMP TABLE for_1079_base_small
DISTRIBUTED BY (bukrs, lifnr, werks)
AS
SELECT
    purchase_contract_code,
    position_line_item_code,
    bukrs,
    lifnr,
    werks,
    zzsrvpos,
    tmp_1,
    tmp_2,
    datbi,
    datab,
    kopos,
    konws,
    service_code,
    price_uom_code,
    netpr,
    kbetr,
    order_euro_svh,
    currency_dogovor
FROM for_1079_base
WHERE purchase_document_subtype_code = 'ZDTL'
  AND (
        zzsrvpos = 'S49'
     OR tmp_1 IS NOT NULL
     OR tmp_2 IS NOT NULL
  );
Что тут делаем:

Оставляем только нужные поля, чтобы не таскать лишний жир по плану.

Сразу фильтруем по тем же условиям, которые и так используются в join’ах.

DISTRIBUTED BY (bukrs, lifnr, werks) — те же ключи, по которым ты джойнишь с b2.

2. Нормально создаём b2_euro под этот join
Сейчас b2_euro у тебя распределён по rn, а join идёт по
unit_balance_code, forwarder_code, plant_code — из-за этого ГП делает дорогой hash redistribute.

Сделаем так:

sql
Копировать код
DROP TABLE IF EXISTS b2_euro;

CREATE TEMP TABLE b2_euro
DISTRIBUTED BY (unit_balance_code, forwarder_code, plant_code)
AS
SELECT *
FROM dm_calc.storage_sales_bundles_weight
WHERE storage_cost_calculation_type_name = 'Логика Европа';
Если хочешь, можно ещё ужать список колонок, но чтобы сохранить 100% совместимость — оставил SELECT *.

3. Сам join b2_euro ↔ for_1079_base_small
sql
Копировать код
-- Здесь уже используем temp-таблицы с согласованным распределением
SELECT
    b2.*,
    fb.purchase_contract_code,
    fb.position_line_item_code,
    fb.kopos,
    fb.kbetr,
    fb.order_euro_svh,
    fb.zzsrvpos,
    fb.tmp_1,
    fb.tmp_2,
    fb.konws,
    fb.service_code,
    fb.price_uom_code,
    fb.netpr,
    fb.currency_dogovor,
    fb.datab,
    fb.datbi
FROM b2_euro b2
JOIN for_1079_base_small fb
  ON fb.bukrs = b2.unit_balance_code
 AND fb.lifnr = b2.forwarder_code
 AND fb.werks = b2.plant_code;
