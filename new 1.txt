ТЗ

  Цель:

  - забирать из YouTrack карточки типа Incident
  - сохранять их в БД так, чтобы можно было:
      - видеть, кто и когда создал инцидент
      - видеть текущее состояние, исполнителя, приоритет и прочие поля карточки
      - хранить внутреннее описание и блок анализа
      - привязывать инцидент к объекту schema.table и/или сущности
      - строить отчеты по инцидентам в приложении

  Что парсим из YouTrack:

  - все карточки Тип карточки = Incident
  - основные поля карточки
  - текст описания
  - поля блока Анализ
  - служебные поля:
      - автор
      - исполнитель
      - состояние
      - приоритет
      - команда/подсистема
      - направление
      - проект
      - время начала сбоя
      - время обнаружения
      - время окончания работ
      - время триггера
      - трудозатраты
  - поля привязки к объекту:
      - Название сущности
      - Название таблицы
  - поле Откуда алерт
  - поле Описание события

  Что должно получиться:

  - одна основная таблица с карточкой инцидента
  - одна таблица истории/обновлений
  - одна таблица связей с задачами

  Логика загрузки:

  1. Получаем список инцидентов из YouTrack
  2. Для каждого инцидента сохраняем текущий срез карточки
  3. Отдельно сохраняем:
      - связи с другими задачами
      - историю изменений/комментарии
  4. При повторной загрузке:
      - основную карточку обновляем по issue_id
      - связи и историю дозагружаем или пересобираем по инциденту

  Что важно для привязки к объекту:

  - сохранять отдельно:
      - entity_name
      - table_name_raw
  - дополнительно вычислять:
      - table_schema
      - table_name
      - object_fqn = schema.table
  - если Название таблицы пришло как dm.sales_account_receivables, разложить на:
      - table_schema = dm
      - table_name = sales_account_receivables
  - если схема не указана, оставить raw как есть

  create table if not exists tech_etl.yt_incident_links (

      linked_issue_key         varchar(32)  not null,

      linked_issue_summary     text         null,

  distributed randomly;

  create index if not exists idx_yt_incident_links_issue_id
      on tech_etl.yt_incident_links (issue_id);

  create index if not exists idx_yt_incident_links_linked_issue_key
      on tech_etl.yt_incident_links (linked_issue_key);

  create table if not exists tech_etl.yt_incident_history (
      issue_id                 varchar(64)  not null,

      on tech_etl.yt_incident_history (issue_id);

  create index if not exists idx_yt_incident_history_event_dttm
      on tech_etl.yt_incident_history (event_dttm);

  Как использовать

  yt_incidents

  - основная витрина по инцидентам
  - тут строить UI и отчеты

  yt_incident_links

  - связь инцидента с задачами на исправление, хотфиксами и дочерними работами

  yt_incident_history

  - история:
      - кто перевел в статус
      - кто менял исполнителя
      - кто писал комментарии
      - как росли трудозатраты

  ———

  Минимальные правила парсинга

  Если Название таблицы:

  - содержит точку, например dm.sales_account_receivables
      - до точки -> table_schema
      - после точки -> table_name
      - целиком -> object_fqn
  - не содержит точку
      - table_schema = null
      - table_name = значение
      - object_fqn = null

  Если поле пустое:

  - сохранять null

  raw_json

  - хранить полный JSON карточки
  - это сильно упростит доработки без повторного перепарсинга
