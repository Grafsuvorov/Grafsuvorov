4. Проверка НЕ теоретическая, а реальная: где именно растут строки?
Самый надёжный способ — сделать пошаговый EXPLAIN ANALYZE на выборке.

4.1. Создаём sample из факта
Чтобы не мучить 157 млн каждую проверку:

sql
Копировать код
DROP TABLE IF EXISTS tmp_base_sample;

CREATE TEMP TABLE tmp_base_sample AS
SELECT *
FROM dm_calc.storage_sales_bundles_amount
LIMIT 100000;  -- 100k строк для анализа

ANALYZE tmp_base_sample;
4.2. База без JOIN
sql
Копировать код
EXPLAIN ANALYZE
SELECT COUNT(*) 
FROM tmp_base_sample base;
Ожидаешь: Actual Rows = 100000

4.3. Добавляем один JOIN и смотрим, растут ли фактические строки
a) material_spec + shape_texts
sql
Копировать код
EXPLAIN ANALYZE
SELECT COUNT(*)
FROM tmp_base_sample base
LEFT JOIN dict_dds.material_specification ms
       ON ms.material_code = base.material_code
LEFT JOIN dict_dds.material_shape_texts mf
       ON mf.shape_code     = ms.shape_code
      AND mf.language_code  = 'R';
👉 Если Actual Rows ≈ 100000, то здесь нет мультипликатора.

b) transport_hub_texts (например, trht)
sql
Копировать код
EXPLAIN ANALYZE
SELECT COUNT(*)
FROM tmp_base_sample base
LEFT JOIN dict_dds.transport_hub_texts trht
       ON trht.transport_hub_code = base.transport_departure_hub_code
      AND trht.language_code      = 'R';
👉 Если Actual Rows ≈ 100000 — тоже ок.

c) transportation_stage_texts
sql
Копировать код
EXPLAIN ANALYZE
SELECT COUNT(*)
FROM tmp_base_sample base
LEFT JOIN dict_dds.transportation_stage_texts trst
       ON trst.transportation_stage_code = base.transportation_stage_code
      AND trst.language_code = 'R';
👉 Если здесь уже, скажем, 200000+ строк → значит trst реально дублирует строки.
