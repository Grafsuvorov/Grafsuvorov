  Сначала посмотри, какие env реально подставились:

  docker compose exec api sh -lc 'env | grep AIRFLOW_DEV'

  Что смотреть в ответах:

  - 200/401/403 на GET /api/v1/dags
  - если 403, значит логин есть, но нет прав
  - если 401, логин/пароль неверный
  - если 404, base url неправильный
  - если 200, тогда надо тестировать конкретный POST dagRuns

  Если раньше работало, а сейчас нет, очень вероятно одно из двух:

  - поменялись AIRFLOW_DEV_USERNAME / AIRFLOW_DEV_PASSWORD в env контейнера
  - раньше дергался другой DAG id, а сейчас другой endpoint

  Чтобы быстро сравнить, выполни ещё:

  docker compose exec api sh -lc 'env | grep AIRFLOW_DEV_DAG_ID'

  И если AIRFLOW_DEV_DAG_ID пустой, приложение сейчас берёт DAG id из имени файла, например:

  - dm_sales_alverse_mlc_meta.yaml -> DAG id dm_sales_alverse_mlc_meta

  Если в Airflow DAG называется иначе, запуск даст ошибку.

  docker compose exec api sh -lc 'env | grep AIRFLOW_DEV'
  docker compose exec api sh -lc 'curl -i -u "$AIRFLOW_DEV_USERNAME:$AIRFLOW_DEV_PASSWORD" "$AIRFLOW_DEV_BASE_URL/api/v1/dags"'
