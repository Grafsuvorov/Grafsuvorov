Граф ломается из-за старого frontend
     Лог показывает:

  - /api/graph/table/ods/rusal/ledisloc_ral?depth=3

  Это старый URL. Новый должен быть:

  - /api/graph/table/ods/%2Frusal%2Fledisloc_ral?depth=3

  Значит backend уже не главный блокер, у тебя frontend контейнер или браузерный cache всё ещё старые.

  2. Твоя проверка через python -c упёрлась в proxy, не в graph.
     Нужно вызывать без proxy так:

  docker compose exec api python -c 'import urllib.request; opener=urllib.request.build_opener(urllib.request.ProxyHandler({}));
  print(opener.open("http://127.0.0.1:8000/api/graph/table/ods/%2Frusal%2Fledisloc_ral?depth=3", timeout=20).read().decode())'

  Что делать сейчас.

  Жёстко обновить frontend:

  docker compose build --no-cache frontend
  docker compose up -d --force-recreate frontend

  Потом в браузере:

  - Ctrl+Shift+R
  - лучше открыть в Incognito

  И сразу проверить лог again:

  docker compose logs --tail=80 api | grep '/api/graph/table'

  Если после этого там всё ещё:

  - /api/graph/table/ods/rusal/ledisloc_ral?depth=3

  то браузер/nginx реально отдаёт старый bundle.

  Если станет:

  - /api/graph/table/ods/%2Frusal%2Fledisloc_ral?depth=3

  но всё равно будет 404, тогда я чиню уже backend graph дальше.

  По странице “эффективность”:

  - это уже отдельная проблема
  - нужен точный URL, который даёт 404
  - или строка из api/frontend логов

  Сейчас сначала добей frontend для графа, потому тут причина уже видна по логам однозначно.
