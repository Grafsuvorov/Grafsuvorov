# Нагрузка команды

В приложении: **Репорты → Загрузка команды** (`/admin/engineering`). По умолчанию открывается **«Доска · сейчас»**, историческая статистика доступна в отдельном режиме **«Аналитика за период»**. Фильтр 30/60/90 дней относится только к исторической аналитике и не влияет на доску и рекомендации.
API: `GET /api/admin/engineering-efficiency?days=30`, доступен инженерам и администраторам.

## Данные

- Пользователи: `tech_etl.app_users`, роли `engineer`, `admin`. Пользователи без задач также видны; отключённые включаются отдельным переключателем.
- Текущее состояние: последний `yt_issue_snapshot` и актуальные поля `State`/`Состояние`/`Статус`, `Assignee`/`Исполнитель` из `yt_issue_custom_field`. Заполненное значение snapshot не заменяется более старым custom field, если известны обе даты загрузки. При отсутствии snapshot задача всё равно включается по custom fields; даты создания и описание не придумываются.
- Личные часы: неудалённые `yt_issue_worklog`, привязка по `author_email`. Для старых строк без email используется однозначное совпадение логина с пользователем приложения.
- Справочник людей строится отдельно: `yt_issue_worklog INNER JOIN app_users ON lower(trim(author_email)) = lower(trim(email))`, без `issue_id`. Любое списание связывает логин с пользователем для всех задач.
- Исполнитель: актуальный custom field «Исполнитель»/Assignee, затем `assignee` из snapshot, затем последнее назначение из timeline. Если назначения отсутствуют, используем автора последнего перехода в «В работе»/«Ожидание релиза», как в существующих отчётах релизов и YouTrack. Источник показан в карточке. Явное снятие исполнителя не заменяется старым автором перехода. Для отображаемых имён поддержано строгое совпадение двух частей в любом порядке: `Dmitriy.Shkretov@rusal.com` ↔ `Shkretov Dmitriy`, `Vasiliy.Ivanov5@rusal.com` ↔ `Ivanov Vasiliy` (конечный цифровой суффикс учётной записи игнорируется только при сопоставлении полного двухчастного имени), а также перестановка частей полного имени из worklog. Нет сопоставления по одной фамилии, транслитерации или приблизительному написанию. Прямое совпадение email/логина и подтверждённый worklog имеют приоритет. При нескольких кандидатах по имени задача не распределяется; сопоставление по полному имени помечается в карточке. Списания по конкретной задаче для её включения в портфель не нужны.
- Инициатор из описания — заказчик, не исполнитель. Закрытые задачи относятся к текущему исполнителю среза, а не историческому исполнителю на дату закрытия.

## Загрузка полного среза

Прежний режим загрузчика выбирает задачи из релизов и не покрывает всю разработку и текучку. Для первого заполнения отчёта нужен полный срез нужного проекта:

```sh
export YOUTRACK_URL=https://yt.rusal.ru
# YOUTRACK_TOKEN и YT_PG_DSN задаются через окружение.
python3 scripts/ytrek_load_to_gp.py --query 'project: DWH'
```

Запуск выполняется в среде загрузчика с `requests`, `urllib3`, `sqlalchemy`, PostgreSQL-драйвером и доступом к YouTrack/Greenplum. Это команда для оператора; приложение само не запускает загрузку и не хранит токен в браузере.

`--query` принимает произвольный запрос YouTrack и заменяет отбор по релизам. Загрузчик также обновляет ранее открытые задачи из БД, даже если они перестали соответствовать запросу: это позволяет увидеть их закрытие или смену исполнителя. Коллекции задач, трудозатрат, активностей и комментариев читаются с пагинацией. Исполнитель извлекается из custom field, email автора worklog сохраняется. Для старой таблицы при необходимости добавляется `author_email`; действующая колонка не меняется. Обычный запуск не очищает весь срез: атомарно заменяются данные каждой загружаемой задачи.

Первый полный запуск может быть длительным. Далее его можно включить в существующее расписание ETL с подходящим запросом; для сокращённого окна обязательно оставлять в запросе недавно завершённые задачи, если их не было в предыдущем срезе. Права токена должны позволять видеть нужные задачи и email; без этого отчёт будет неполным. Не используйте `--truncate` для частичной загрузки.

## Доска и подбор исполнителя

Доска показывает активных сотрудников в отдельных колонках, открытые задачи сгруппированы на работу, очередь, ожидание релиза и уточнение. Задачи без сопоставленного исполнителя находятся во входящих. Есть поиск сотрудника, фильтр категории и сортировка по текущей загрузке. Часы за период не участвуют в сортировке и подборе.

Нажмите карточку задачи или укажите её номер / объекты вручную. Кандидаты рассчитываются автоматически. Есть три режима: баланс, меньше текущей работы, больше контекста по объектам. Выбранная задача исключается из загрузки при сравнении кандидатов; на самой доске она остаётся у текущего исполнителя. Исполнитель автоматически в YouTrack не меняется: карточка содержит ссылку для назначения.

Нагрузка — сравнительная эвристика: 3 балла за рабочую задачу, 1 за очередь, 0,25 за ожидание релиза, 0,5 за уточнение, плюс остаток известных оценок разработки и очереди / 8. Остаток — оценка в часах минус полные загруженные списания по задаче, независимо от окна аналитики. Нулевая оценка считается отсутствующей; исчерпанные оценки помечаются отдельно и не выдаются за свободную ёмкость. ISO-периоды с неделями/днями автоматически не преобразуются в рабочие часы.

Контекст — одинаковые объекты (4 балла за задачу) либо прямая зависимость из `depends_on` каталога (2 балла), максимум 8. В режиме баланса контекст вычитается из нагрузки; в режиме контекста его вес увеличен втрое; в режиме ёмкости не влияет на порядок. В деталях кандидата показаны конкретные задачи и объекты/связи. Одной схемы или общего предка недостаточно, чтобы объявить объекты связанными.

Объекты берутся из описания YouTrack и обогащаются `release_objects`; связи — из существующего кэша метаданных приложения. Если каталог недоступен, остаётся сравнение одинаковых объектов; интерфейс указывает доступность связей. Отпуска, внеплановая работа и незагруженные задачи не учитываются, процент занятости не рассчитывается.

Доска может повторно запрашивать данные каждую минуту при открытой вкладке браузера. Это обновление экрана по БД, а не запуск ETL: даты свежести среза остаются видимыми.

## Метрики

- Открытый портфель: все задачи текущего исполнителя в открытом статусе, независимо от окна анализа. Известный открытый статус имеет приоритет над старым `resolved_at` после переоткрытия.
- Завершённые статусы: `Done`, `Fixed`, `Завершена`. `Duplicate` и `Отклонено` тоже закрывают задачу, но исключены из средних трудозатрат и длительности выполнения.
- Все остальные перечисленные статусы (включая DEV. Подготовлено к релизу, Ожидание релиза, Проверка / Тест, ПРОД. Подлежит проверке) открытые. Для неизвестного/пустого статуса используется `resolved_at`.
- «Закрыто в срезе» включает все закрытые задачи; рядом указаны закрытые за период, без даты и отменённые/дубли. Фильтры «Все закрытые» и «Закрытые за период» разделены.
- Дата закрытия: `resolved_at` или последний переход в текущий закрытый статус из timeline. `updated_at` не заменяет дату закрытия. Без даты задача видна в общем числе закрытых, но не учитывается в периоде и длительности.
- Списано: личные трудозатраты по `work_date` внутри окна. Часы не размножаются на количество объектов задачи и не переносятся на её исполнителя.
- Часы / задача: среднее полных трудозатрат **всех участников** по выполненным задачам (Done, Fixed, Завершена), закрытым в окне, с ненулевыми списаниями; отмены и дубли исключены. Рядом показан размер выборки. Ноль списанных часов не означает бесплатную задачу и не входит в среднее.
- До закрытия: среднее календарное время от создания до закрытия, включая ожидание, по завершённым задачам.
- Без обновлений ≥14 дней: открытая задача без изменения `updated_at` 14 дней; это сигнал для просмотра, а не доказательство отсутствия работы.
- Учёт времени / фонд: личные часы / (будние дни × выбранные 4/6/8 часов). Без производственного календаря и отпусков, не оценка свободной ёмкости или эффективности.

Категория «Витрины · Tech ETL»: автор `tech_etl` (включая email с таким логином), либо шаблон `Email инициатора` + `MR` + `Витрина`. Поддерживаются обычные и жирные Markdown-поля, один и несколько объектов. В карточке показан признак классификации. Другие задачи со snapshot объединены в категорию «Разработка и текучка». Если snapshot отсутствует и задача найдена только в custom fields, она показана в категории «Без описания»: источник Tech ETL не предполагается, но задача входит в общий портфель. Время выполнения SQL из описания не используется как рабочее время.

В отчёте показаны самая поздняя и самая ранняя загрузки срезов, открытые задачи без сопоставленного исполнителя, часы неизвестных авторов и часы по задачам без snapshot. Эти индикаторы помогают оценить качество данных; даты загрузки не гарантируют полноту охвата YouTrack.

CSV выгружает все задачи выбранного сотрудника/категории/статуса с учётом поиска, а не только текущую страницу. В колонках времени указаны общие часы задачи; личные часы отдельно видны в режиме «Списывал время».
