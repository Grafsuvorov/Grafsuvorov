. Структура yaml-файла дага для сущности 
entity_name: KAIZEN_LOADER
entity_id: 65
schedule:
  DEV: "45 9 * * *"
  PREPROD: "45 9 * * *"
  PROD: "30 3 * * *"
dbt:
  dbt_command: 'dbt run --select tag:KAIZEN_LOADER --exclude tag:disabled'
  additional_vars: '{"is_skip": false,"ENTITY_NAME": "KAIZEN_LOADER", "ENTITY_ID": 65, "old_meta_enabled": true}'
  on_failure_callback: True
clickhouse:
  enabled:
    DEV: True
    PREPROD: True
    PROD: True
  poke_interval_watcher: 120
  tables:
    - dag_name: dm_kaizen_personnel_involvement_meta
      dbt_model: dm_s_kaizen_personnel_involvement
    - dag_name: dm_kaizen_submitted_and_implemented_meta
      dbt_model: dm_s_kaizen_submitted_and_implemented

Параметр	Описание
entity_name	Название (код) сущности
entity_id	Идентификатор сущности
schedule	Расписание с разбивкой по стендам
schedule.DEV	Расписание для стенда DEV
schedule.PREPROD	Расписание для стенда PREPROD
schedule.PROD	Расписание для стенда PROD
dbt	Блок настроек работы dbt
dbt.dbt_command	Команда запуска DBT
dbt.additional_vars	Дополнительные переменные
dbt.on_failure_callback	Флаг включения алертинга на уровне дага
clickhouse	Блок настроек выгрузки данных в ClickHouse
clickhouse.enabled	Блок настроек включателей выгрузки данных в ClickHouse с разбивкой по стендам
clickhouse.enabled.DEV	Флаг включения выгрузки данных в ClickHouse для стенда DEV
clickhouse.enabled.PREPROD	Флаг включения выгрузки данных в ClickHouse для стенда PREPROD
clickhouse.enabled.PROD	Флаг включения выгрузки данных в ClickHouse для стенда PROD
clickhouse.poke_interval_watcher	Временной интервал между проверками готовности витрин к выгрузке, сек (по умолчанию 120 сек)
clickhouse.tables	Блок соответствия моделей и дагов выгрузки в ClickHouse (список)
clickhouse.tables.dag_name	Название дага выгрузки модели в ClickHouse
clickhouse.tables.dbt_model	Название модели, которую должен выгрузить соответствующий даг в ClickHouse
2. Настройка конфигурации yaml-файла для переключения сущности для расчета на dbt 
Откройте файл конфигурации в репозитории ETL:

config_files/dbt_dags/{ENTITY_NAME}.yaml

2.1. Команды и переменные 
Настройте следующие параметры:

Параметр	Описание	Пример
dbt_command	Команда запуска DBT	dbt run --select tag:KAIZEN_LOADER --exclude tag:disabled
additional_vars	Дополнительные переменные	См. ниже
Пример конфигурации:

dbt_command: 'dbt run --select tag:KAIZEN_LOADER --exclude tag:disabled'

additional_vars: >
  {
    "is_skip": false,
    "ENTITY_NAME": "KAIZEN_LOADER",
    "ENTITY_ID": 65,
    "old_meta_enabled": true
  }

⚠️ Важно: Поле "is_skip": false должно оставаться таковым до завершения полной миграции.

2.2. Расписание 
В процессе переключения расписание для стендов DEV и PREPROD не меняется, для стенда PROD расписание копируется из дага расчета ETL.

Среда	Параметр	Значение
PROD	schedule	30 3 * * *
2.3. Блок ClickHouse 
Для стенда PROD блок clickhouse должен быть включен:

clickhouse:
  enabled:
    PROD: true

2.4. Блок callback 
Установить параметр on_failure_callback в значение true.

3. Предварительные требования 
Перед началом переключения расчета сущности на dbt убедитесь, что выполнены следующие условия:

Сущность полностью протестирована на стенде PROD в части dbt.
В задаче аналитика на сверку расхождений сущности в dbt и etl аналитик указал, что сверка завершена и можно ставить в PROD
Согласована дата и время на переключение расчета сущности на dbt.
На стенде DEV протестирован даг расчета сущности в dbt и выгрузки в ClickHouse (далее CH) в части airflow в режиме выгрузки в CH:
clickhouse:
 enabled:
   DEV: True

Должен быть подтвержденный МР репозитория dbt на инженерную задачу по переключению расчета сущности на dbt
Пример:
https://prod.gitlab.dwh.rusal.com/dwh/dbt/-/merge_requests/607

В модели dbt_greenplum_elt/models/tech_etl/tech_etl_s_dbt_entities_meta.sql
для переключаемой сущности установить флаг on_dbt в значение true

(65,'KAIZEN_LOADER',true),

Должен быть подтвержденный МР репозитория etl на инженерную задачу по переключению расчета сущности на dbt
Пример:
https://prod.gitlab.dwh.rusal.com/dwh/etl/-/merge_requests/4071

4. Процесс переключения 
Выполнить следующие шаги строго в указанном порядке:

Чек-лист переключения 
Оба дага (ETL и DBT) перевести в режим Disable
Создаем релизные ветки в репозиториях ETL и DBT
Из заранее подготовленных МР (п. 3) сливаем в соответствующие релизные ветки
Из релизных веток сливаем в ветки main соответствующих репозиториев
Запустить релизный даг DBT
Запустить релизный даг ETL
Обновить флаг on_dbt путем запуска модели tech_etl_s_dbt_entities_meta из ветки main
dbt run --vars '{is_skip_by_entities_meta: False, is_skip: False}' --select tech_etl_s_dbt_entities_meta -t dev

dbt run --vars '{is_skip_by_entities_meta: False, is_skip: False}' --select tech_etl_s_dbt_entities_meta -t prod

DAG {ENTITY_NAME}_dbt перевести в режим Enable. При этом даг запустится сам.
Проверить результат работы дага
Даг отработал без ошибок
В журнале dbt ошибки отсутствуют
Успешно отработали даги выгрузки данных в ClickHouse, указанные в блоке мапинга п. 1
5. Откат изменений в случае возникновения проблем при переключении расчета сущности на dbt 
5.1. Отключение дага DBT и включение дага ETL 
# 1. Отключить DAG DBT
{ENTITY_NAME}_dbt: disabled

# 2. Включить DAG ETL
{ENTITY_NAME}: enabled

5.2. Откат изменений в репозиториях ETL и DBT 
Создать релизные ветки в обоих репозиториях для отката изменений
Создать МР с изменениями обратными в ранее созданных МР (п. 3)
Провести релиз указанных МР в обоих репозиториях
Запустить модель dbt_greenplum_elt/models/tech_etl/tech_etl_s_dbt_entities_meta.sql на стендах DEV и PROD
dbt run --vars '{is_skip_by_entities_meta: False, is_skip: False}' --select tech_etl_s_dbt_entities_meta -t dev

dbt run --vars '{is_skip_by_entities_meta: False, is_skip: False}' --select tech_etl_s_dbt_entities_meta -t prod
