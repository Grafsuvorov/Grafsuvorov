Цепочка ORACLE-GG-KAFKA-NIFI-S3 работает независимо от связки AIRFLOW-GP.

Файлы из ORACLE складываются в S3 по мере их поступленияв KAFKA и никак не завязаны на рассписание AIRFLOW. Т.е. если AIRFLOW будет простаивать, то в S3 накопится какое-то количество файлов. Т.е. чем дольше будет простой AIRFLOW, тем дольше потом джобы будут вычитывать файлы потому, что DAG при запуске обрабатывает все ордера в статусе 1. Для больших таблиц это может приводить к тому, что время работы джоба превысит требуемые 20 минут.

NIFI читает из кафки сообщения от ГГ, преобразует все типы полей схемы parquet-файла в строки для исключения ошибок с некорректным типом полей (тип поля сообщения из кафки в NIFI при автоматическом формировании схемы parquet определяется по содержимому поля. Одно и тоже поле может быть как типа int, так и float, что ломает пакетную загрузку через PXF).
После приведения всех типов к строкам NIFI складывает данные в S3 в паркеты.

Расписание AIRFLOW раз в несколько минут (зависит от расписания) запускает загрузку данных из паркета в DWH.

Загрузка паркетов в гринплам осуществляется через ордерную систему.
Каждый запуск DAGa формирует ордера (на каждый новый файл по одному ордеру для шаблона INCREMENT и раз в день на всю папку для шаблона DAILY).
Метаданные по таблицам так же берутся из ордерной системы.
Действия над ордером логируются.

Ордерная система 
goldengate.load_manager_jobs - метаданные джоба.
goldengate.load_manager_orders_{table_name} - ордера на загрузку по конкретной таблице.
goldengate.load_manager_log - логи загрузки всех ордеров.
