1. Получить token логином:

  curl --noproxy '*' -s -X POST http://127.0.0.1:15312/auth/login \
    -H 'Content-Type: application/json' \
    -d '{"email":"ТВОЙ_EMAIL","password":"ТВОЙ_ПАРОЛЬ"}'

  2. Скопировать из ответа access_token и подставить:

  curl --noproxy '*' -s http://127.0.0.1:15312/api/orderbreaches \
    -H "Authorization: Bearer TOKEN"

  3. Для карточки таблицы так же:

  curl --noproxy '*' -s "http://127.0.0.1:15312/api/card/dm/account_turnover_by_counterparty" \
    -H "Authorization: Bearer TOKEN"

  Если хочешь без ручного копирования token, можно одной командой:

  TOKEN=$(curl --noproxy '*' -s -X POST http://127.0.0.1:15312/auth/login \
    -H 'Content-Type: application/json' \
    -d '{"email":"ТВОЙ_EMAIL","password":"ТВОЙ_ПАРОЛЬ"}' | sed -n 's/.*"access_token":"\\([^"]*\\)".*/\\1/p') && \
  curl --noproxy '*' -s http://127.0.0.1:15312/api/orderbreaches -H "Authorization: Bearer $TOKEN"

  Пришли мне:

  - ответ /api/orderbreaches с token
  - ответ /api/card/dm/account_turnover_by_counterparty с token

  Тогда станет ясно:

  - backend реально отдает нарушения или нет
  - и ломается ли карточка на данных, а не на роутинге.
