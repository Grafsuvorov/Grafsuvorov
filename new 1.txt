Да, этот блок считается так.

  Во фронте карточка берёт поля:

  - row.releases_count
  - row.objects_count
  - row.tasks_count
  - row.hours_total

  Это видно в src/components/AdminEngineeringPage.jsx:502.

  Сам SQL для Среза по типам поставок такой, в api/main.py:1280:

  SELECT
      release_bucket,
      COUNT(*) AS releases_count,
      COALESCE(SUM(objects_count), 0) AS objects_count,
      COALESCE(SUM(tasks_count), 0) AS tasks_count,
      COALESCE(SUM(minutes_total), 0) / 60.0 AS hours_total
  FROM release_rollup
  GROUP BY release_bucket
  ORDER BY releases_count DESC, objects_count DESC

  Что это значит по смыслу:

  - Релизы = 925
    это количество записей в release_rollup с release_bucket = 'release'
  - Хотфиксы = 224 объекта
    если вы про число 224 на карточке, то это objects_count
    то есть сумма количества строк/объектов из release_objects по всем релизам этого типа
  - Задачи = 42
    это не глобально уникальные задачи по всему типу
    это SUM(tasks_count) из release_rollup

  А tasks_count внутри одного релиза считается так, в api/main.py:1193:

  SELECT
      release_id,
      COUNT(DISTINCT task_id) AS tasks_count,
      COUNT(DISTINCT engineer) AS engineers_count,
      COUNT(DISTINCT creator) AS creators_count,
      COALESCE(SUM(minutes), 0) AS minutes_total
  FROM task_fact
  GROUP BY release_id

  То есть:

  - сначала для каждого release_id считается число уникальных task_id
  - потом в type_breakdown эти значения суммируются по типу поставки

  Важный нюанс:

  - если одна и та же задача попадала в несколько релизов, она будет учтена несколько раз
  - значит 42 задач это:
      - сумма уникальных задач внутри каждого релиза данного типа
      - а не COUNT(DISTINCT task_id) по всему бакету целиком

  Если хотите, я могу сразу поменять это поведение на более честное для бизнеса:

  - либо уникальные задачи по типу поставки
  - либо оставить как сейчас, но переименовать в вхождений задач или задач в релизах, чтобы не путало.
